# Bounded Muse source Worker launch

Select the installed Muse adapter and read its exact source/package manifest.
Use its `muse_worker_launcher.py` and `schemas/muse-launch.schema.json`, rather
than `muse_session_host.py` or a lifecycle-only package's generic preflight.
No adapter availability result overrides role, phase or ownership requirements.

This lane admits source/test/handoff work with explicit Meta 1.3 Contributor,
YOLO and reasoning effort. Stage/production authority, environment operations,
other roles, host credential mounts and detached services remain unqualified.
Never silently narrow a full delivery assignment to fit it. If a source handoff
is the authorized operation, reflect that exact operation in the envelope and
keep its downstream delivery owner and dependencies explicit.

Before launch, persist a fresh native UUIDv7 and distinct Worker actor with the
existing dispatch reservation. Bind that exact native/generation, register the
Worker identity and claim its primary item under that identity. Read current
controller actor/native/epoch and claim generation. Do not borrow a live task,
claim or another runtime's actor. Keep runtime executables, settings, ledger
SQLite home, state/evidence and the installed adapter outside the mutable Worker
workspace. Qualification/recovery must not load an unrelated business session.

Prepare the checked Muse launch configuration with those identities, immutable
Linux tool-image ID, selected Docker context/daemon and the existing model
settings path. No credentials belong in the assignment/configuration/manifest.
Run its execution check and then the launcher in the new cmux workspace/surface;
record transport and native IDs under the existing dispatch reservation. Native
MSP owns the fixed shell/write denial and equivalent YOLO posture. All mutations
are mediated by the session-bound MCP bridge and owned Linux containers.

Read the [complete execution contract](../../../agent-loop/README.md#muse-source-worker-execution).
Read the actual startup skill/profile identities, model/permissions, tool and
join evidence. A bounded invocation returns after completion and queued
coordination handling. A later continuation uses `--resume` for the original
native/task/claim/controller tuple, preserving its edits and commits. It does
not create another controller or background model timer. Pending outcome
publication is not Dispatcher handling or Issue acceptance; reconcile those
states under the ordinary role contract.

An unresolved startup, result, native process, MCP bridge or owned container
retains its closed execution pin and original custody. Recover that original
operation; never replace it or delete its journal to make admission pass. Install
and qualify this lane before selecting it for new work. Existing sessions adopt
nothing merely because an installation link moved.
